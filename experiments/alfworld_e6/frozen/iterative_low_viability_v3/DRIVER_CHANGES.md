## Monetary guard

A new ledger starts at zero and excludes the historical V2 spend. Limits fixed before paid calls: $4 top-up; $25 adaptation plus confirmation; $29 cumulative maximum. At top-up completion, `topup_cost_baseline.json` freezes returned cost, retained failed reservations, committed subtotal and physical attempt count. The cap state records its SHA256. During adaptation each physical request enforces `total_committed + proposed_reservation < frozen_topup_committed + 25`, additionally bounded by 29. Unused top-up allowance is not transferred. No spending or reservations are reset, forgiven or refunded. The child policy factory binds the V3 transport and same cap/baseline files.

## Core and combined input provenance

`verify_core() -> dict[str, Any]` verifies `core_manifest.json` against the exact previously committed qualified-evidence record, prior screening hash, all 48 original executions and all 48 valid aliases. It checks original episode IDs, semantic trace hashes, combined ZERO hashes, and stored three-trace IDs/order/hashes. Core selection uses the old `selected_valid_indices`, without resampling; only Z4 uses the historical seeded selection.

`import_core() -> dict[str, Any]` creates byte-identical copies under the new run and a `core_import.json` record. It refuses existing or partially copied core artifacts. `combined_screening() -> dict[str, Any]` requires one new qualified ID and returns `[154, 158, 159, Z4]`, verifying all 64 original observations and cross-task episode uniqueness.

`frozen_valid_traces(task, task_screen, *, source_run=None)` retains its validation and adds an optional read-only source root to inspect the prior run. `selected_failures(task, traces)` returns exactly the prior three traces for core tasks and the normal seeded selection for Z4.

`freeze_inputs()` uses that combined set and obtains exactly one existing-provider reference per task, then calls normal `serialize_low(..., 0.0, 16, reference, rich=True)`. Its immutable input manifest additionally binds combined-screening, core-manifest, and top-up cost-baseline hashes. Failed reference acquisition retains task membership; successful references cannot be regenerated by rerunning this stage. `verify_input_set()` revalidates the same combined records and exact selected evidence before adaptation.

## Frozen execution

Thus one optimizer lineage, three designer calls, typed feedback, all gates, solvability, 4→8 endpoints, thirty adaptation episodes including CONTROL, reserve16, freeze boundary, CONTROL, and fresh K16 remain unchanged. No C4, D/I, HIGH or outer AEA is added.

`decision_for()` has one report-only preregistered change requested by the root review of the new user protocol: with zero K16 B_L hits, partial signal requires at least two accepted environments with actually completed n=16 confirmations that miss B_L. Endpoint success without completed confirmation does not satisfy “successes with failed confirmation.” Correctness, two B_L hits, infrastructure, and one B_L hit retain their prior precedence. This changes no execution or optimizer feedback.

## Artifact APIs

- `screening.json`: only newly inspected top-up tasks; `qualified` has zero or one task. Adds `core_tasks` and `core_manifest_sha256`.
- `core_import.json`: prior commit, manifest hash, all 48 prior episode IDs and original per-task screening records.
- `combined_screening.json`: exact combined four-task qualification and source hashes, written by freeze-inputs.
- `topup_cost_baseline.json`: immutable top-up cost snapshot, verified in each adaptation physical request.
- Existing task/reference/adaptation/confirmation filenames and schemas are unchanged.

## Offline validation

Real historical core verification passed with 96 exact file bindings, zero environment calls and zero APIs. Ruff, formatting, and strict mypy on the staged driver pass; imported unchanged historical scripts have preexisting strict typing issues, so standalone strict checking uses `--follow-imports=silent` and `MYPYPATH=scripts`. Independent test coverage is staged by the review agent. The final source-binding audit records all unchanged/changed/new helper hashes.

A narrow CLI/report boundary preserves non-report stage exceptions in `stage_interruption.json` as `{stage, error: {type, kind, reason}}`, returns exit status 1, and stops an initialized cap without retry. In particular, a successfully qualified top-up followed by reference/input-freeze infrastructure failure reports `INCONCLUSIVE`; a genuine correctness failure reports `IMPLEMENTATION_FAILURE`. Neither is mislabeled as a failed top-up. Reporting-only exceptions do not modify the experiment's status. Existing operation journals still prevent repeated references and paid operations.
